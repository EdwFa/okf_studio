# OKF Studio

Приложение для работы с документами и формирования баз знаний в формате
[OKF](https://cloud.google.com/blog/products/data-analytics/how-the-open-knowledge-format-can-improve-data-sharing)
(Open Knowledge Format: файлы Markdown с YAML-шапкой и полем `type`).

Домен знаний → группы документов → документы → разделы и рекомендации.
Документ после загрузки автоматически разбивается на разделы по собственным
заголовкам; текст разделов дословный. Разбивку, заголовки, текст и уровни
рекомендаций (УУР, УДД) можно проверить и поправить вручную, сверяясь с
оригиналом, который открыт рядом.

## Запуск

```bash
npm install          # один раз
npm run setup:python # один раз: окружение Python для чтения PDF и DOCX (нужен uv)
npm run dev          # сервер на 127.0.0.1:8100, интерфейс на http://localhost:3100
```

Приложение работает рядом с Лукой (порты 3000 и 8000) и ничего в ней не меняет.
Входа пока нет, поэтому сервер слушает только этот компьютер.

## Где лежат данные

`~/.okf-studio/` (можно сменить переменной `OKF_STUDIO_HOME`). Всё — обычные файлы:

| Путь | Содержимое |
|---|---|
| `studio.json` | Домены и их группы, в порядке показа |
| `log.md` | Общий журнал изменений |
| `docs/<id>/meta.json` | Карточка документа: группа, метаданные, статус, счётчики |
| `docs/<id>/source/` | Исходный файл |
| `docs/<id>/text.txt` | Извлечённый текст |
| `docs/<id>/auto.json` | Разделы, как их построила автоматическая разбивка (не правится) |
| `docs/<id>/sections.json` | Рабочие разделы: автоматическая разбивка плюс ручные правки |
| `docs/<id>/history.jsonl` | Журнал правок документа |

## Устройство

| Папка | Что в ней |
|---|---|
| `packages/okf-core` | Общий с Лукой код: разбивка на разделы и выделение рекомендаций (`sections.ts`), разметка рекомендаций как редактируемая структура (`recs.ts`), запись файлов OKF (`bundle.ts`), чтение PDF и DOCX (`python/extract_text.py`) |
| `server` | Сервер (Fastify): хранилище (`store.ts`), фоновая очередь разбора (`jobs.ts`), выгрузка OKF (`export.ts`), маршруты (`app.ts`) |
| `web` | Интерфейс (Next.js): список доменов, групп и документов (`app/page.tsx`), экран документа (`app/doc/page.tsx`) |

### Общий код с Лукой

`okf-core/src/sections.ts` и `okf-core/python/extract_text.py` — пока точные
копии файлов Луки (`k-dense-pi/server/src/knowledge-sections.ts` и
`server/src/helpers/knowledge_helper.py`). Тест `shared-with-luka.test.ts`
падает, если копии разошлись: правило разбивки, исправленное в одном месте,
нужно перенести в другое. Следующий шаг — подключить `okf-core` в Луке вместо
её собственных файлов.

Выгрузка группы повторяет раскладку, которую читает база знаний Луки:
`<группа>/index.md`, `<группа>/<документ>.md`, `<группа>/<документ>/NN_<раздел>.md`,
`<группа>/<документ>/recommendations.md`.

## Публикация в Луку

Кнопка «Опубликовать в Луку» на странице группы записывает группу в базу
знаний Луки (`~/.kady/pi-agent/knowledge/`, сменить — переменной
`LUKA_AGENT_DIR`) и обновляет навык `kb-<группа>` для агентов. Код —
`server/src/publish.ts`.

- Публикуются только документы со статусом «проверено»; после публикации они
  получают статус «опубликовано».
- Документ, изменённый после публикации, здесь снова черновик, а в Луке
  остаётся прежняя версия — до следующей публикации после проверки.
- Удалённые или перенесённые документы убираются из Луки при следующей публикации.
- Скрытая группа записывается, но агентам не показывается.
- Документы помечаются `curated`: Лука не пересобирает их файлы из исходного
  текста (для этого в Луке нужна версия с поддержкой этой пометки).
- Чужие группы и навыки не трогаются: папка группы помечена файлом
  `.okf-studio`, без него публикация в существующую папку отказывает.
- «Снять с публикации» удаляет группу из Луки; здесь документы остаются.

Агенты видят изменения в новых чатах Луки.

## Соответствие стандарту OKF 0.2

Пакет, который получается при выгрузке и публикации, проходит проверку на
соответствие спецификации (`checkBundle` в `okf-core/src/conformance.ts`, §11):

- у каждого файла документа, раздела и сводки рекомендаций есть шапка с `type`;
- оглавления `index.md` без шапки, записи — ссылки с описанием; только корневое
  несёт `okf_version`;
- журнал `log.md` без шапки, записи под заголовками-датами, новые сверху;
- стандартные поля: `resource` (ссылка на первоисточник), `tags`, `sources`
  (откуда текст), `generated` (чем создан файл), `verified` (кто и когда
  проверил: документ и каждый раздел отдельно), `status` (`draft` для
  черновика, `stable` для проверенного), `stale_after` (срок пересмотра).

Чего пока нет: отдельных файлов-понятий (термины, сокращения, рекомендации как
самостоятельные записи). Файл в пакете — документ или его раздел, то есть
разобранный первоисточник.

## Что сделано и что дальше

Этап 1 (сделано): домены и группы; загрузка PDF, DOCX, Markdown и текста с
фоновым разбором; карточка документа; просмотр оригинала рядом с разделами;
правка заголовков, уровней и текста; разделение и объединение разделов;
таблица рекомендаций с правкой УУР и УДД; статусы «черновик / проверено»;
журнал правок; выгрузка OKF архивом.

Публикация в Луку (сделано): кнопка «Опубликовать в Луку» на странице группы.

Этап 2: редактор таблиц, поиск по всем доменам (с индексом SQLite),
распознавание сканов. Этап 3: сравнение версий, конспекты моделью, вход и роли,
правила разбивки для других типов документов.
